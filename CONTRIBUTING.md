# Contributing / Contribuire

## English

**Send community pull requests to `dev`, never to `main`.** Fork the repository and create a task branch in your fork. `main` and `dev` are the only permanent branches of this repository. Only the owner may open a promotion PR to `main`; other PRs targeting it are closed automatically with guidance to use `dev`.

`dev` requires documentation, desktop build/vault and UI checks. `main` additionally requires a dependency audit, an up-to-date branch, a review, code-owner review, approval of the latest push and resolved review conversations. The owner retains an explicit PR-only administrative bypass; direct pushes, force pushes and deletion remain protected.

Write commit messages in English. Every project README must contain English first and Italian second, updated together. Use the issue forms for bugs, features and usage questions. Maintainers assign priority and workflow labels; `good first issue` identifies scoped tasks and `help wanted` invites contributions.

Never upload real credentials, private keys, production logs, personal vaults or private audio/video. Report vulnerabilities through GitHub private security reporting. Tests must use fixtures and isolated data.

No automatic merges, installer publication or deployment. Only stable releases are published, after an explicit owner decision. Public source availability does not itself grant an open-source license; no project license has been selected yet. Dependency licenses remain applicable.

## Italiano

**Invia le pull request della community a `dev`, mai a `main`.** Crea un fork e un ramo di lavoro nel tuo fork. `main` e `dev` sono gli unici rami permanenti di questa repository. Solo il titolare può proporre una PR di promozione a `main`; le altre PR dirette lì vengono chiuse automaticamente indicando di usare `dev`.

`dev` richiede controlli su documentazione, build/archivio e interfaccia. `main` richiede anche verifica delle dipendenze, ramo aggiornato, revisione, revisione del proprietario del codice, approvazione dell’ultimo invio e conversazioni risolte. Il titolare conserva un bypass amministrativo esplicito utilizzabile solo tramite PR; invii diretti, riscrittura e cancellazione restano protetti.

Scrivi i commit in inglese. Ogni README del progetto deve contenere prima inglese e poi italiano, aggiornati insieme. Usa i moduli per bug, funzionalità e domande. I manutentori assegnano priorità e stato; `good first issue` identifica attività circoscritte e `help wanted` invita a contribuire.

Non caricare credenziali reali, chiavi private, log di produzione, archivi personali o audio/video privati. Segnala le vulnerabilità tramite il canale privato GitHub. I test devono usare dati fittizi e isolati.

Nessuna unione automatica, pubblicazione di installer o distribuzione sul server. Sono previste soltanto release stabili, su decisione esplicita del titolare. Il codice pubblico non implica automaticamente una licenza open source: quella del progetto non è stata ancora scelta. Restano valide le licenze delle dipendenze.
