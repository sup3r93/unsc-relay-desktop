# CodeQL follow-up: 207 open findings

## English

Snapshot taken from GitHub on 17 November 2026, main `5ca0d75a84502a3eaa80612e08a462bd1f675874`, after release 0.2.18. All 207 open IDs are listed exactly once below: 157 test/smoke, 46 product and four vendor cipher-primitive findings. The 76 previously approved dismissals are outside this open snapshot and are not changed. This is a source security follow-up; the already published 0.2.18 installer is not replaced.

### Confirmed defects and fixes

1. OpenSSH config preview rejected a linked file but accepted a linked ancestor. A parent could also be redirected after preview while an identical external config passed the original-content check. The new boundary rejects both cases before creating output. Bounded reads use a held file handle; temporary output uses CreateNew and cleanup does not traverse redirected parents.
2. Update download accepted a linked destination directory and wrote the installer outside the selected tree. It now rejects linked ancestors before making an HTTP request and rechecks after receiving the response, before opening output. Metadata must match the exact version-derived asset, a positive ID and a 64-digit hexadecimal digest. Download and hash use the same exclusively held file handle instead of closing and reopening by name. Failure cleanup is limited to a file this invocation actually created, after rechecking its parents.

An additional regression redirects the destination during the synthetic HTTP request and confirms no external file is created. The new parent-link regressions were run against the old implementation first: both failed because the old code accepted the redirected locations. They pass after correction, including assertions that outside file contents/directory entries are unchanged. A Windows regression also attempts to open the in-progress installer for overwrite during the verification callback: access is denied and the verified bytes remain intact.

### Findings retained with evidence

The table combines the prior call-chain review with the current owning code and new regressions. Local owner-selected file access/process launch is intentional functionality; it is not automatically a remote traversal/execution defect. The test assembly and explicitly requested smoke modes use synthetic data. Vendor AES primitives implement the surrounding negotiated cipher modes; the actual two-block NIST CTR/CBC and non-ECB transport-list regressions remain active. No vendor cryptography is rewritten merely to suppress a finding.

No alert is manually dismissed here; no query, language, test, branch protection or security setting is disabled. The scanner may continue reporting local path flow despite the runtime boundaries. This does not claim elimination of same-user hostile filesystem races or comprehensive penetration testing.

## Italiano

Esaminato lo snapshot corrente di 207 avvisi aperti: 157 nelle prove/smoke, 46 nel prodotto e quattro nelle primitive crittografiche della libreria. La tabella precedente elenca ciascun ID una sola volta. Le 76 chiusure già autorizzate non vengono modificate.

Corrette due lacune reali nei confini dei percorsi: la configurazione SSH poteva attraversare una cartella collegata, anche sostituita dopo l’anteprima; il download dell’installer poteva essere scritto attraverso una destinazione collegata. Le regressioni aggiunte fallivano sul codice precedente e passano dopo la correzione, verificando che file e cartelle esterni restino intatti. L’installer viene ora scaricato e verificato sullo stesso file tenuto aperto in esclusiva, con metadati convalidati prima della rete e pulizia limitata ai file realmente creati dall’operazione.

Compilazione senza avvisi/errori e 307 controlli sintetici superati nelle suite elencate sopra. Nessun archivio personale, app installata, account reale, dispositivo fisico o servizio VPS modificato. È una correzione del sorgente successiva alla 0.2.18: l’installer già pubblicato non viene sostituito.

Gli altri avvisi conservano motivazioni verificabili sul contesto di uso locale, sui test e sulle primitive crittografiche. Non equivalgono a 207 vulnerabilità riparate né a un risultato senza avvisi. Nessuna segnalazione chiusa manualmente, nessun controllo, query, lingua o protezione disattivata. Non viene dichiarata immunità assoluta contro corse sul filesystem di un processo ostile con gli stessi privilegi.
